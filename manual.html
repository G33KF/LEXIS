What LEXIS adds

ALEAPP and iLEAPP parse a phone extraction into hundreds of artifacts. LEXIS opens their report and adds the views an examiner works in. This manual covers only what LEXIS adds, view by view. It describes version 1.2.5.

Read-onlyEvidence files open from temporary copies. Tags, OCR text and AI results go to separate databases beside the case.
Several devicesOne investigation case holds many devices, with joint views and co-presence.
TraceableEvery value points back to its artifact, record and source file on the device.

Each device in the case tree has these nodes: Timeline, Statistics, Map, Media Gallery, Documents, Tagged Items, Search, Indicators, Extraction Files, Chats, and Analyzed Data (the artifacts by category). The Timeline and Map nodes appear only when the device has dated records or positions. The case node adds Shared analysis for all the devices together.

Cases and devices

Investigation case

A case file (.lexiscase) holds a name, a Proceeding no., and the devices. Each device has a label, a colour, and a report (a folder, a .lava file or a portable case zip). Paths below the case file are stored relative to it, so a case folder can be moved. Labels must be unique.

The case page shows a card per device: its platform, records, artifacts with data, tagged items, and the names and numbers that identify its user. Names on more than one device lists names spelled the same on two or more devices: a lead, not an identification.

Accounts Overview

One row per account of each app or service, merged from the account and profile artifacts: name, username, phone, e-mail, UID, services, and Read from. Selecting a row shows every value with the artifact and column it came from. A profile picture is shown only if it is a file in the extraction, never fetched from the internet. Tokens, keys and saved passwords are left out.

Artifact tree

Analyzed Data groups artifacts into macro categories (Calls, Contacts, Messages, Location Related, Media, User Accounts & Details…), then by app. Artifacts with no records go to a No data group. The setting Show "Data by application" adds a parallel tree by app.

Across devices

The case node's Shared analysis group works on all the devices of the case at once. Every view has a Devices list, one coloured checkbox per device: untick a device to leave it out.

Joint Timeline

Every non-empty date column of every record becomes an event; the events of all ticked devices are merged in time order, each with a chip in its device colour. Filter by artifact, by period, by text (search syntax), newest first. A histogram per day sits above the list: click a bar to jump to that day.

Joint Map and zones of interest

Positions come from any artifact with a latitude/longitude column pair; positions at 0,0 are dropped. There is one layer per device and artifact, in the device colour. Route joins each device's positions in time order. A period can be set; then positions without a time are left out.

Zones of interest groups the positions shown into circles and counts visits:

SettingDefaultMeaning
Radius (m)200A position joins the nearest zone within this distance, otherwise it starts a new zone.
New visit after (min)60Two positions of one device in a zone further apart in time than this are two visits.
Together within (min)10Visits of two devices count as together when they overlap or are this close in time.

List… opens the zones table (first and last seen, visits, positions, devices, together), with the visits of the zone picked. Only zones of more than one device keeps the shared places.

Co-presence

Co-presence finds positions of different devices that are close in space and in time. Only positions that carry a time are compared.

ParameterDefaultEffect
Radius (m)100Largest distance between two positions (great-circle distance)
Time window (min)10Largest time difference, either side of each position
Devices at least2Smallest number of devices in a group
SourcesallWhich location artifacts are compared, with their counts

Matching pairs are chained into groups: devices close at the same time, directly or through other positions, form one co-presence. Groups are numbered by time. Each row shows the devices, from, to, span, positions, the largest distance of the matched pairs, and the centre. The lower list shows every position of the selected group with its device, time, source and record; double-click opens the record. Show on map draws one numbered circle per co-presence.

A co-presence means the records place the devices near each other. It does not show that the devices, or their users, met. At most 10,000 position pairs are used: if more exist, LEXIS says so; narrow the radius or the window.

Common Contacts

Run reads the contacts, calls, messages and app accounts of every device and keeps the identifiers found on at least two devices.

  • Sources: contact artifacts, communication artifacts (calls, SMS/MMS, chats, voicemail) and artifacts of messaging and social apps.
  • Types: phone, e-mail, WhatsApp LID, WhatsApp group, App ID, App username. A WhatsApp JID counts as its phone number. App IDs and usernames are compared only within the same app.
  • Numbers: spaces, dashes, dots and brackets are removed; 8 to 15 digits are required. The comparison uses the last 9 digits, so +39 333… on one device matches 333… on another. The number shown is the international form when one was recorded.

Each row shows the identifier, its type, the devices, where it was found and the names recorded beside it. The lower list shows every record with the value as stored; Open jumps to it. Filters (text, type, sources, devices) apply without a new run.

Two numbers from different countries with the same last 9 digits would be merged. Check the values as stored before relying on a match.

Media gallery and origin

Files shown

  • Linked to records: the media ALEAPP/iLEAPP tied to a record (for example a chat attachment).
  • Whole extraction: every picture, video and audio file in the extraction, read-only. Files at the same device path as a report file still get their sent/received data.

Filters

Type (image, video, audio, file), App, Origin, Date (message time, else file modified), and text (name, artifact, path, chat, sender). The app is read from the package folder in the device path (/data/data/<package>, Android/media/<package>…), else from the artifact; about 80 packages are named (WhatsApp, Telegram…).

Origin: where a file came from

The origin is decided from two facts only: the file's path on the device and the chat messages that carry it. Nothing is guessed from the picture itself.

OriginRule
Device galleryIn the user's own storage: /Media/DCIM/ on iOS; on Android the shared storage (/sdcard, /storage/emulated/N, SD cards), except app folders under Android/, hidden folders and caches.
CameraTaken with the phone's camera. Android: DCIM/Camera/ or a camera folder such as DCIM/100ANDRO in the shared storage. iOS: the Photos library says the back or front camera imported it (iLEAPP's Photos.sqlite artifacts must be in the report).
ScreenshotsScreenshots and screen recordings. Android: a Screenshots, Screen recordings or ScreenRecorder folder, or a name such as Screenshot_… or Screen_Recording_…. iOS: the Photos library marks it as a screenshot or screen recording (iLEAPP's Photos.sqlite artifacts); without them the status line says so and the list stays empty.
Sent or receivedAt least one chat message points to the file.
SentAt least one of those messages is outgoing.
ReceivedAt least one of those messages is incoming.
CacheA folder in the path is a cache, thumbnails or temp folder.
System filesSystem or app-install paths (/system/, /vendor/, /data/app/, /System/, /Applications/…).

The direction of a message comes from the chat artifact's own direction column (outgoing, sent, from me…). A picture received and then forwarded is both Received and Sent. If the artifact has no direction column, the message counts as Sent or received only.

Same content, other file

In Linked to records, files of the same size are hashed (SHA-256); equal hashes are copies of one content, for example the same photo saved by two apps. A file shows its copies' messages too, marked same content, other file. They do not change its own origin.

Sent / received history

Selecting a tile opens Sent / received history in the details pane: one row per message that carried the file (or a copy of it): direction and artifact, who (to a chat, from a sender, group or not), and when. Click a row to open that message in its table.

Media viewer

Double-click a tile: pictures zoom (wheel, buttons, double-click for fit/100%) and pan by dragging; video and audio play; PDFs show in a sandboxed viewer with scripts off. Programs and scripts are never run: they are only shown in their folder. Other files open as a read-only temporary copy.

OCR and AI on media

Each tile has a checkbox. Checked files are what the toolbar buttons work on, on every page the filters keep. All files start checked, so use Uncheck all first, then check the files you want. The right-click menu works on the selected tiles instead: one or many.

OCR

Two engines, both offline: Tesseract, carried by LEXIS with 12 languages (English, Italian, Chinese simplified and traditional, Arabic, Russian, Albanian, French, German, Spanish, Portuguese, Romanian), and Windows OCR with the languages installed in Windows. Defaults: files up to 20 MB, scanned PDFs up to 200 pages; pictures over 80 million pixels are skipped and counted. The text is stored per file in _reader_text.db, never in the evidence.

Image AI

Describe + OCR takes JPEG, PNG, GIF and WebP up to 20 MB; other formats are counted as left out. Classify uses the categories in AI settings (by default weapons, drugs, identity documents, cash or payment cards, screenshots, vehicles, people, documents, other). A stopped run resumes where it stopped.

Video analysis

A frame every 10 % of the duration (or every N seconds), at most 30 frames, each described by the vision model; the audio track is transcribed when the video is under one hour. The output is one timeline per video (mm:ss seen / said), with the SHA-256 of each frame sent. Temporary frames are deleted afterwards.

Details pane

Above the tabs: a preview (picture, or player for video and audio), Open and Show in folder; for e-mails the original body in a sandboxed view; for gallery media the sent/received history.

Chats

The Chats node lists every app with a conversation view, then the user's accounts. Chats are split by local account, by backup file, by SIM card (Android SMS/MMS) or by own number (iOS Messages), whenever the artifact records it.

  • Private or Group: group when the chat ID is a group ID (@g.us, @chatroom…) or more than one person besides the user wrote in it.
  • Chat list: chat, type, account, participants, message count, first and last message, last text; filter per column, by type and by account.
  • Chat view: bubbles or table; participants matched to their contact record by identifier, never by display name; search with Ctrl+F; filters by direction, sender, kind (text, media, images, videos, audio, locations, replies, system messages) and date.
  • Recovered messages (from a Recovered column or not in the active database) are marked Recovered (deleted) with a dashed outline.
  • WeChat voice messages (SILK) play in LEXIS.
  • Export: an HTML report in a WhatsApp or Telegram look, one page per chat, with an evidence block (source files and SHA-256) at the top. The examiner's tags and notes are left out unless you tick them. Every export is logged.

Search

One syntax for search, filters, timeline and chats:

WriteFinds
a bboth words
a | beither word
-awithout the word
"exact phrase"the phrase
/regex/a regular expression

Search in

  • Report data: the artifact records, by category.
  • File contents: the text inside the extraction's documents, databases, property lists, JSON/XML/HTML and text files. The text is read once and kept, so later searches are fast. A scanned PDF with no text is listed as Needs OCR; right-click to read it.
  • AI results: translations, descriptions, transcripts and analyses.

Exclude technical fields leaves out hashes, UUIDs, encoded data, paths and IDs.

Results

One table: origin (report data, file content, needs OCR, AI analysis), category, artifact, date, app, device, where the hit is, text, source. Narrow it with Within the results, the filter of each column, or the facets with counts. Tag results tags the rows selected or shown. The last 50 searches are kept per case, outside the case folder.

Keyword lists

Load list… takes a .txt or .csv in any language and encoding: one keyword per line (or split on a separator), duplicates dropped, # lines as comments. The list is searched as any of the words.

Extraction files and SQLite

Extraction Files

  • The extraction as a read-only tree by device path: zip, tar, tar.gz, folder, or iTunes/Finder backup (encrypted ones unlock with the password for the session only).
  • Read by: the artifacts that read each file, with a filter to keep only those.
  • Identify types types every file from its first bytes; Search inside searches the bytes of the listed files (UTF-8 and UTF-16).
  • Hex, text and tree viewer; archives (zip, APK, Office, tar…) browsed inside without unpacking; MD5, SHA-1 and SHA-256 on demand; tag files.
  • Documents is the same view for PDF, Office, OpenDocument, RTF and iWork files.

SQLite reader

  • Opens a read-only copy. Apply the write-ahead log switches between what the app saw last (with the WAL) and the main file alone.
  • Tables, views and indexes with counts and schema; filter, sort, export CSV; one read-only SELECT/PRAGMA at a time.
  • Recovered carves records a query no longer returns: older page versions (main file and WAL), free space, journal and freelist pages, each with origin, page, offset and a confidence. Finding nothing is not proof that nothing was deleted.

Plist and structured data

XML and binary plists as a tree with the key path of every node; NSKeyedArchiver archives resolved; nested plists, JSON and protobuf decoded.

Timeline, map, statistics

Per device, the Timeline and Map work as the joint ones above. Statistics shows:

  • Parties: top 10 and last 10 one-to-one parties, with means, exchanges, out/in and last contact; you choose which means are counted. Group chats are not counted.
  • Locations: the ten places (zones of 200 m) with most positions, with visits and first/last time.
  • User activity: a 12-month calendar, year by year, weekday × hour, and the busiest days (click to open the day in the timeline).

Indicators

  • Indicators and hash sets: STIX2 files (for example MVT feeds) and MD5/SHA-1/SHA-256 lists, loaded by the examiner; nothing is downloaded. Every text cell and the extraction's file list are checked; domains also match their subdomains.
  • Root / jailbreak traces (Magisk, Cydia, Sileo…): a trace does not mean the device is rooted now.
  • Security settings: on Android the weakening settings and the security patch age; on iOS the version age and passcode changes.
  • Crypto addresses (Bitcoin, Litecoin, Dogecoin, Tron, XRP, Ethereum, Monero, TON) and BIP-39 seed phrases, reported only when their checksum holds.
  • Tag by rules: a text file of Tag: keyword or Tag: /regex/ lines; Tag all matches applies them.

AI

AI is off until Use AI is ticked and a model server is set. Defaults are local: Ollama and LM Studio. Any OpenAI-compatible endpoint can be added (its key protected by Windows DPAPI), and the Claude CLI can be used after a warning that data leaves the machine. Each server is marked local, LAN or remote; a remote one asks before sending. One model is chosen per job: text, vision, transcription, video frames.

  • On records: Summarize, Translate, Explain (what a record is and each value), questions on the records, and a thematic review in batches that resumes.
  • Complete analysis: an objective and the data categories to read; optionally translate, describe images and transcribe audio first; then triage and a report that cites its records.
  • Audio: whisper.cpp on this machine, installed from Set up whisper.cpp / models…; each downloaded file is kept only if its size and SHA-256 match the published ones. Opus, AMR, M4A and MP3 are converted by LEXIS's own ffmpeg.
  • MCP server: the open case, read-only, on this machine only, with a secret token; LM Studio, Claude Desktop or any MCP client can query it.
  • Records kept: every result with its prompt and citations, and every send (when, where, which model, how many characters, the exact text) in _reader_ai.db; the Send log tab shows it.
AI output is a review aid, not a finding. Every answer lists its cited records (click to open); citations to records that were not sent, and lines without a source, are flagged.

Tags, exports, portable case

Tags and notes

Tags (Evidence, Important, Suspicious, Follow up, Irrelevant, or your own) with Ctrl+1…Ctrl+5, and notes, on records, chats, media and extraction files. They are kept in _reader_tags.db beside the case. Tagged Items lists them and exports an HTML or JSON report.

Exports

Any table to CSV, JSON or HTML, following the filters in view, or only the checked rows. HTML reports carry their media in a folder beside the page. The Exports button lists every export of the session: what, when, from which device, to which file.

Portable case

  • One zip with the case and, optionally, the reader exe beside it, so the recipient needs nothing else.
  • Content by category, or tagged records only; media; the source files of the included artifacts or every file the parsing read; tagged files. Every copied file is checked against ALEAPP's copy.
  • SHA256SUMS.txt covers every file and can be signed with the examiner's ECDSA P-256 key, kept non-exportable in the Windows key store; give the recipient its fingerprint by another channel.
  • Verify package checks a received zip without opening it: intact, ALTERED, or not a portable case. An altered case opens with a red banner.
